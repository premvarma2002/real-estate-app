# 📱 Android Deployment Guide — Real Estate App

> A complete step-by-step reference for building and deploying the Android APK using **EAS Build (Expo Application Services)**.

---

## 🛠️ Tech Stack

| Tool | Purpose |
|------|---------|
| **Expo SDK 54** | React Native framework |
| **EAS Build** | Cloud-based APK/AAB builder |
| **EAS CLI** | Command-line tool to interact with EAS |
| **Clerk** | Authentication (requires publishable key) |
| **Supabase** | Backend / database |

## 📋 Prerequisites

Before building, make sure you have the following installed:

```bash
# Install EAS CLI globally
npm install -g eas-cli

# Login to your Expo account
npx eas-cli login
```

Also ensure you have:
- ✅ An [Expo account](https://expo.dev)
- ✅ The project linked to EAS (`projectId` in `app.json`)
- ✅ Environment variables set on EAS (see below)

---

## 🔐 Step 1 — Set Environment Variables on EAS

> ⚠️ **Important:** The `.env` file is **NOT** uploaded during EAS Build.
> You must manually set all `EXPO_PUBLIC_*` variables on the EAS dashboard.

Run these commands once (or whenever values change):

```bash
# Clerk Publishable Key
npx eas-cli env:set --name EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY \
  --value "your_clerk_key_here" \
  --environment preview \
  --visibility plaintext \
  --non-interactive

# Supabase URL
npx eas-cli env:set --name EXPO_PUBLIC_SUPABASE_URL \
  --value "https://your-project.supabase.co" \
  --environment preview \
  --visibility plaintext \
  --non-interactive

# Supabase Anon Key
npx eas-cli env:set --name EXPO_PUBLIC_SUPABASE_KEY \
  --value "your_supabase_key_here" \
  --environment preview \
  --visibility plaintext \
  --non-interactive
```

> 💡 Repeat the above for `--environment production` and `--environment development` as needed.

**Verify variables are set:**
```bash
npx eas-cli env:list
```

## ⚙️ Step 2 — Configure `app.json`

The `android/` folder is **gitignored** and regenerated by EAS on every build.
All Android configuration must live in `app.json`.

### Key Android settings in `app.json`:

```json
{
  "expo": {
    "android": {
      "package": "com.realestateapp",
      "versionCode": 1,
      "usesCleartextTraffic": true,
      "permissions": [
        "android.permission.INTERNET",
        "android.permission.ACCESS_NETWORK_STATE",
        "android.permission.CAMERA",
        "android.permission.READ_MEDIA_IMAGES",
        "android.permission.READ_MEDIA_VIDEO",
        "android.permission.VIBRATE",
        "android.permission.SYSTEM_ALERT_WINDOW"
      ],
      "adaptiveIcon": {
        "backgroundColor": "#E6F4FE",
        "foregroundImage": "./assets/images/android-icon-foreground.png",
        "backgroundImage": "./assets/images/android-icon-background.png",
        "monochromeImage":  "./assets/images/android-icon-monochrome.png"
      }
    }
  }
}
```

> **Why `usesCleartextTraffic: true`?**
> Android 9+ blocks non-HTTPS traffic by default. Clerk OAuth browser redirects require this to be enabled.

> **Why permissions in `app.json` and not `AndroidManifest.xml`?**
> Because `/android` is in `.gitignore`. EAS generates the `AndroidManifest.xml` from `app.json` on every build, so direct edits to the manifest file are lost.

## 📦 Step 3 — Configure `eas.json`

```json
{
  "cli": {
    "version": ">= 16.0.0",
    "appVersionSource": "local"
  },
  "build": {
    "development": {
      "developmentClient": true,
      "distribution": "internal",
      "node": "22.12.0",
      "android": { "buildType": "apk" }
    },
    "preview": {
      "distribution": "internal",
      "node": "22.12.0",
      "android": { "buildType": "apk" }
    },
    "production": {
      "node": "22.12.0",
      "android": { "buildType": "app-bundle" }
    }
  }
}
```

| Profile | Output | Use Case |
|---------|--------|----------|
| `development` | `.apk` | Dev builds with dev-client (for Expo Go replacement) |
| `preview` | `.apk` | Internal testing / share with testers |
| `production` | `.aab` | Google Play Store submission |

## 🚀 Step 4 — Trigger a Build

### Build a Preview APK (for sharing/testing):
```bash
npx eas-cli build --platform android --profile preview --non-interactive
```

### Build a Production AAB (for Play Store):
```bash
npx eas-cli build --platform android --profile production --non-interactive
```

### Build a Development APK (with dev-client):
```bash
npx eas-cli build --platform android --profile development --non-interactive
```

After running, EAS will output a **build URL** like:
```
See logs: https://expo.dev/accounts/prem_varma10/projects/real-estate-app/builds/<build-id>
```

Visit the URL to monitor progress and download the APK once done (~10–15 min).

## 🐛 Common Issues & Fixes

### ❌ App crashes immediately on launch

**Cause:** `EXPO_PUBLIC_CLERK_PUBLISHABLE_KEY` is empty in the APK.
**Fix:** Set the env variable on EAS (Step 1). The `.env` file is local-only.

---

### ❌ Network requests failing on Android 9+

**Cause:** Android 9+ blocks cleartext HTTP traffic.
**Fix:** Add `"usesCleartextTraffic": true` under `android` in `app.json`.

---

### ❌ Storage/Camera permissions denied

**Cause:** Missing permission declarations in manifest.
**Fix:** Add the required permissions to `app.json` under `android.permissions[]`.
Use scoped permissions for newer Android versions:
- Android 13+: Use `READ_MEDIA_IMAGES` / `READ_MEDIA_VIDEO` instead of `READ_EXTERNAL_STORAGE`

---

### ❌ Changes to `AndroidManifest.xml` not applying

**Cause:** `/android` is in `.gitignore` — EAS regenerates it from `app.json`.
**Fix:** Always make Android config changes in `app.json`, not in the manifest file directly.

## 📁 Key Files Reference

| File | Purpose |
|------|---------|
| `app.json` | Main Expo config — Android permissions, package name, icons, plugins |
| `eas.json` | EAS build profiles (dev / preview / production) |
| `.env` | Local environment variables (NOT uploaded to EAS — set on EAS dashboard) |
| `android/` | Auto-generated native Android project (gitignored — do NOT edit directly) |

## 🔄 Deployment Checklist

Before every build, verify:

- [ ] All `EXPO_PUBLIC_*` env vars are set on EAS for the target environment
- [ ] `app.json` has the correct `versionCode` (increment for each Play Store release)
- [ ] Icons exist at the paths specified in `app.json`
- [ ] `eas.json` profile matches your target (`preview` for APK, `production` for AAB)
- [ ] Changes are committed and pushed to GitHub before building
